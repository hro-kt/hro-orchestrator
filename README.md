# hro-orchestrator

開催日の司令塔。**Azure の電源**と**当日ジョブの引き金**だけを持つ。

## 何をしないか

**当日の回し方は持たない。** 常駐3本の起動・再投入・停止は既存の
`hro-ops race-day`(ops_job の kind=`race_day`)が担う。ここはそれを
**投入するだけ**。

★2026-10-17 に「親が2本走って同じレースを2回買いかける」事故を起こしている。
  当日の制御を2箇所に持たせない。

```
hro-orchestrator (Linux, 常時)
  ├ 開催日か判定            … nl_ra
  ├ Azure VM の起動/停止    … Windows は開催日だけ
  └ race_day を投入         → 既存のオーケストレータが当日を回す
```

## 設計の芯: 計画と実行を分ける

`plan.py` は**純粋関数**。「いまの状態」→「次にやるべき行動の列」。
DB も Azure も触らないのでテストできる。副作用は `runner.py` だけが持つ。

この5日間に潰した障害は、どれも**副作用の中に判断が埋まっていて試せない**形だった。

## 安全規則(コードで守る)

- **ジョブが走っている機は止めない**。close_day / tax_seal は Windows で走る
- **「VM が起動した」≠「agent が動いている」**。ハートビートを確認してから投入
- **起動に失敗したら鳴らす**。人が手で起こせる時刻に動く(第1発走の数時間前)
- **冪等**。何度走らせても安全
- **止めるのは締めが終わってから**(tax_seal の完了を見る)

## 使い方

```bash
hro-orchestrator plan            # 何をするつもりかだけ出す(副作用なし)
hro-orchestrator run --dry-run   # 行動も出すが実行しない
hro-orchestrator run             # 実行する
hro-orchestrator status          # VM / agent / ジョブの現状
```
